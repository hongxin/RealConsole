## v1.36.3 (2025-11-08) - Markdown 渲染一致性优化

**主题**: Web 终端 Markdown 渲染样式统一

**问题背景**:
- **传统模式** (`.line-markdown`): ✅ 完整赛博朋克霓虹风格
- **回合模式** (`.markdown-content`): ❌ 无样式（纯黑白文本）
- **用户反馈**: "传统模式更加好看，建议保持一致性"

**核心改动**:
1. **CSS 样式统一** - DRY 原则
   - 为所有 Markdown 元素添加 `.markdown-content` 选择器
   - 修改 17 个 CSS 规则组（h1-h6, strong, em, code, pre, p, ul/ol, blockquote, a, hr, table, img）
   - 新增代码：~30 行（选择器扩展）
   - 代码重复：0（使用选择器组合）

2. **赛博朋克霓虹风格** - 统一视觉体验
   - 标题：青色→粉色渐变 (#00f0ff → #ff006e)
   - 粗体：白色发光
   - 代码块：霓虹绿色 (#39ff14)
   - 列表标记：霓虹粉色
   - 引用块：霓虹紫色边框
   - 表格：赛博朋克网格
   - 链接：霓虹粉色 + 悬停发光

3. **极简主义验证** - H2 下划线检查
   - ✅ 确认 H2 无下划线（符合极简美学）
   - 保持视觉简洁，避免过度装饰

**技术实现**:
```css
/* Before: 只有传统模式 */
.line-markdown h1 { ... }

/* After: 两种模式统一 */
.line-markdown h1,
.markdown-content h1 { ... }
```

**测试验证**:
- 创建测试脚本：`/tmp/test_markdown_styles.sh`
- Web 服务器：http://127.0.0.1:7799
- 验证内容：h1-h6, 粗体, 斜体, 代码, 列表, 引用, 链接, 表格等

**效果对比**:
- Before: 传统模式 ✅ / 回合模式 ❌ / 一致性 ❌
- After:  传统模式 ✅ / 回合模式 ✅ / 一致性 ✅

## v1.36.1 (2025-11-08) - 核心后端重构

**主题**: Phase 1 - 易经从装饰层到核心哲学

**根本性转变**:
- ❌ v1.36.0: 步骤 → 按序号映射爻位 → 生成卦象（后置装饰）
- ✅ v1.36.1: 步骤本身**就是**爻，步骤性质决定爻位（内在融合）

**核心洞察**（用户原话）:
> "每个步骤不就是相当于从初、二、三、四、五、上爻吗？然后其意图步骤的变动更改编辑，不就是错综复杂等若干演化吗？"

**新增模块**:
1. **StepAnalyzer** - 步骤性质分析（+620 行）
   - 6 种语义性质：Preparation → Execution → Decision → Processing → Finalization → Cleanup
   - 对应爻位：初爻"潜龙勿用" → 上爻"亢龙有悔"
   - 阴阳平衡分析

2. **SequenceValidator** - 序列合理性检验（+650 行）
   - 21 条验证规则（5 个严重、8 个警告、8 个信息）
   - 示例：检测"删除在读取之前"、"缺少清理步骤"

3. **SituationAnalyzer** - 统一态势分析（+280 行）
   - 复杂度评估（Simple/Moderate/Complex）
   - 风险等级（Low/Medium/High）
   - 优化建议生成

**哲学升华**:
- 从"占卜算命"（娱乐）→"态势测算分析"（科学）
- 易经不是装饰，而是系统的内在逻辑
- 步骤 = 爻，编辑 = 变化，序列 = 卦象

```

              ├─ 否 → 直接返回
              └─ 是 → 执行工具 → 结果返回 LLM → 再次解析 → ...
```

**设计要点**:
- 最多 5 轮迭代（防止无限循环）
- 每轮最多 3 个工具调用
- 工具执行超时控制
- 安全沙箱（工具白名单）
