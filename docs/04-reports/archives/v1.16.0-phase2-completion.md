#### 多维度建议系统 (`suggestion.rs` - 349 行)
**位置**: `src/error_fixer/suggestion.rs`

**核心功能**:
- 四维度评分机制：
  - **相关性** (Relevance): 40% 权重 - 与当前错误的相关程度
  - **可行性** (Feasibility): 30% 权重 - 成功执行的概率
  - **安全性** (Safety): 20% 权重 - 操作风险评估
  - **学习价值** (Learning Value): 10% 权重 - 是否帮助用户理解

**数据结构**:
```rust
pub struct Suggestion {
    pub command: String,
    pub description: String,
    pub relevance: f64,      // 0.0-1.0
    pub feasibility: f64,    // 0.0-1.0
    pub safety: f64,         // 0.0-1.0
    pub learning_value: f64, // 0.0-1.0
    pub recommended: bool,
}

pub fn score(&self) -> f64 {
    self.relevance * 0.4 +
    self.feasibility * 0.3 +
    self.safety * 0.2 +
    self.learning_value * 0.1
}
```

#### 风险评估系统 (`risk.rs` - 444 行)
**位置**: `src/error_fixer/risk.rs`

**核心功能**:
- **四级风险分类**:
  - ✅ Safe (安全) - 直接执行
  - ⚠️ Low (低风险) - 提示确认
  - 🔶 Medium (中风险) - 详细说明
  - 🔴 High (高风险) - 强制二次确认

- **8 种风险因素识别**:
  1. Deletion (删除操作)
  2. PrivilegeEscalation (权限提升)
  3. SystemFile (系统文件操作)
  4. Network (网络操作)
  5. Recursive (递归操作)
  6. Force (强制操作)
  7. DataLoss (数据丢失风险)
  8. Irreversible (不可逆操作)

**智能风险计算**:
```rust
// 取最高风险因素 + 累积效应
let max_risk = factors.max(|f| f.impact * f.base_risk());
let multiplier = 1.0 + (factors.len() - 1) * 0.15;  // 每多一个因素 +15%
let final_score = (max_risk * multiplier).min(1.0);
```

**检测模式**:
- `rm -rf` / 系统目录 → High
- `sudo` 命令 → Medium/High
- `dd` / `mkfs` / 磁盘操作 → High
- `shutdown` / `reboot` → High

## 🎨 设计亮点

### 1. 一分为三哲学

Phase 2 的三个模块体现"一分为三"设计理念：

```
           增强错误系统
                │
        ┌───────┼───────┐
        │       │       │
    识别层   分析层   预测层
        │       │       │
   风险评估  建议系统  下一步预测
```

- **识别层** (`risk.rs`): 快速识别命令风险，提前预警
- **分析层** (`suggestion.rs`): 深度分析，提供多维度建议
- **预测层** (`predictor.rs`): 前瞻性预测，引导用户下一步操作

### 2. 智能风险计算

**不是简单平均，而是累积效应**:

```rust
// ❌ 错误做法：平均风险（会稀释风险）
score = total_risk / factor_count

// ✅ 正确做法：最高风险 + 累积效应
max_risk = max(factors.map(|f| f.impact * f.base_risk()))
multiplier = 1.0 + (factor_count - 1) * 0.15
final_score = max_risk * multiplier  // 每多一个因素增加 15%
```

**示例**:
- `rm file.txt` → 单一删除因素 → 0.3 (Low)
- `rm -rf /etc/config` → 删除 + 递归 + 系统文件 → 0.81 (High)
- `sudo rm -rf /etc/config` → 四个因素 → 0.93 (High)

### 3. 概率预测机制

基于实际工作流的概率分配：

```rust
// 高概率 (>= 0.75): 常见且符合逻辑的下一步
git commit → git push (0.85)
cargo build → cargo test (0.8)

// 中概率 (0.5-0.75): 可能但不是必然
cargo test → cargo run (0.75)
npm install → npm run dev (0.8)

// 低概率 (0.25-0.5): 特定场景才需要
cargo build → cargo build --release (0.6)
npm install → npm run build (0.5)
```
