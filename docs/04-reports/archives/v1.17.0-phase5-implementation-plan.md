## 🔧 详细设计

### A.1: 过滤条件下推到 UnifiedTracer

**问题**:
当前实现全量加载后过滤，内存和性能开销大：
```rust
// 当前实现
let all_entries = tracer.query_by_dimension(Dimension::Memory, capacity).await?;
Ok(all_entries
    .into_iter()
    .filter(|e| e.entry_type == trace_type)  // ❌ 内存中过滤
    .collect())
```

**优化方案**:
将过滤条件下推到 UnifiedTracer：
```rust
// 新设计
pub async fn query_by_dimension_with_filter(
    &self,
    dimension: Dimension,
    limit: usize,
    filter: Option<QueryFilter>,  // ✅ 过滤下推
) -> Result<Vec<TraceEntry>> {
    let entries = self.custom_entries.read().await;

    let filtered = entries
        .iter()
        .filter(|e| e.dimension == dimension)
        .filter(|e| filter.as_ref().map_or(true, |f| f.matches(e)))  // ✅ 提前过滤
        .take(limit)
        .cloned()
        .collect();

    Ok(filtered)
}

pub struct QueryFilter {
    pub entry_type: Option<EntryType>,
    pub importance: Option<Importance>,
    pub tags: Option<Vec<String>>,
    pub context_id: Option<String>,
}
```

**预期收益**:
- 📊 减少内存分配：只加载匹配条目
- 📊 提升查询速度：提前过滤，减少迭代次数
- 📊 支持组合查询：一次调用完成复杂过滤

**修改文件**:
- `src/tracer/unified_tracer.rs` (新增 QueryFilter 和方法)
- `src/memory/manager.rs` (使用新 API)

**测试**:
```rust
#[tokio::test]
async fn test_query_with_filter() {
    let filter = QueryFilter {
        entry_type: Some(EntryType::User),
        importance: Some(Importance::Important),
        tags: None,
        context_id: None,
    };

    let results = tracer
        .query_by_dimension_with_filter(Dimension::Memory, 100, Some(filter))
        .await
        .unwrap();

    // 验证所有结果都匹配过滤条件
    assert!(results.iter().all(|e| e.entry_type == EntryType::User));
    assert!(results.iter().all(|e| e.importance == Some(Importance::Important)));
}
```

### B.1: Tag 索引设计与实现

**问题**:
标签查询需要遍历所有条目：
```rust
// O(n) 复杂度
let results: Vec<_> = all_entries
    .into_iter()
    .filter(|e| e.tags.contains(&tag))
    .collect();
```

**索引设计**:
```rust
pub struct UnifiedTracer {
    // ... 现有字段 ...

    /// Tag 索引: tag -> [entry_index]
    tag_index: Arc<RwLock<HashMap<String, Vec<usize>>>>,
}

impl UnifiedTracer {
    pub async fn add_entry(&self, entry: TraceEntry) {
        let mut custom = self.custom_entries.write().await;
        let mut tag_idx = self.tag_index.write().await;

        // 更新索引
        let entry_idx = custom.len();
        for tag in &entry.tags {
            tag_idx
                .entry(tag.clone())
                .or_insert_with(Vec::new)
                .push(entry_idx);
        }

        // LRU 清理（需要同步更新索引）
        if custom.len() >= self.custom_capacity {
            self.remove_oldest_from_index(&mut tag_idx, &custom[0]).await;
            custom.pop_front();
        }

        custom.push_back(entry);
    }

    /// 基于索引的标签查询
    pub async fn query_by_tag(&self, tag: &str) -> Vec<TraceEntry> {
        let tag_idx = self.tag_index.read().await;
        let custom = self.custom_entries.read().await;

        tag_idx
            .get(tag)
            .map(|indices| {
                indices.iter()
                    .filter_map(|&i| custom.get(i))
                    .cloned()
                    .collect()
            })
            .unwrap_or_default()
    }
}
```

**复杂度对比**:
- **无索引**: O(n) 时间，O(1) 空间
- **有索引**: O(k) 时间，O(t) 空间（k=结果数，t=标签总数）

**权衡**:
- ✅ **查询加速**: 大数据集下明显提升
- ⚠️ **内存开销**: 每个标签维护索引列表
- ⚠️ **维护成本**: LRU 清理时需要同步更新索引

**适用场景**:
- ✅ 标签查询频繁
- ✅ 数据集较大（1000+ 条）
- ❌ 标签数量极多（索引爆炸）

### C.1: UnifiedTracer 容量溢出测试

**测试场景**:
```rust
#[tokio::test]
async fn test_unified_tracer_capacity_overflow() {
    let tracer = create_test_tracer_with_capacity(100);

    // 添加 200 条数据
    for i in 0..200 {
        let entry = TraceEntry::new(
            Dimension::Memory,
            EntryType::User,
            Status::Success,
            format!("Entry {}", i),
        );
        tracer.add_entry(entry).await;
    }

    // 验证容量限制
    assert_eq!(tracer.custom_entries_count().await, 100);

    // 验证 LRU 策略（最旧的被移除）
    let entries = tracer.query_by_dimension(Dimension::Memory, 200).await.unwrap();
    assert!(entries[0].content.contains("Entry 100")); // 前 100 条被移除
}
```

**验证点**:
- ✅ 容量限制生效
- ✅ LRU 策略正确
- ✅ 最旧数据被移除
- ✅ 最新数据保留

### D.1: 查询性能追踪

**设计**:
```rust
pub struct PerformanceTracker {
    query_times: Arc<RwLock<VecDeque<QueryMetrics>>>,
}

pub struct QueryMetrics {
    pub query_type: String,
    pub duration: Duration,
    pub result_count: usize,
    pub timestamp: DateTime<Utc>,
}

impl UnifiedTracer {
    pub async fn query_all_with_tracking(&self, limit: usize) -> Result<Vec<TraceEntry>> {
        let start = Instant::now();
        let results = self.query_all(limit).await?;
        let duration = start.elapsed();

        // 记录性能指标
        self.perf_tracker.record(QueryMetrics {
            query_type: "query_all".to_string(),
            duration,
            result_count: results.len(),
            timestamp: Utc::now(),
        }).await;

        Ok(results)
    }

    /// 获取性能报告
    pub async fn performance_report(&self) -> PerformanceReport {
        let metrics = self.perf_tracker.query_times.read().await;

        PerformanceReport {
            total_queries: metrics.len(),
            avg_duration: metrics.iter().map(|m| m.duration).sum::<Duration>() / metrics.len() as u32,
            slowest_query: metrics.iter().max_by_key(|m| m.duration).cloned(),
            // ...
        }
    }
}
```

**使用场景**:
```rust
// 开发调试
let report = tracer.performance_report().await;
println!("平均查询时间: {:?}", report.avg_duration);
println!("最慢查询: {:?}", report.slowest_query);

// 性能测试
assert!(report.avg_duration.as_millis() < 100, "平均查询时间过长");
```

## 📝 风险评估

### 高风险

1. **索引维护复杂度**
   - 风险: LRU 清理时索引同步可能出错
   - 缓解: 充分的边界测试，验证索引一致性

2. **内存开销增加**
   - 风险: 索引占用额外内存
   - 缓解: 可配置开关，默认关闭索引

### 中风险

3. **API 设计变更**
   - 风险: QueryFilter 设计可能不够灵活
   - 缓解: 先实现基本功能，后续迭代扩展

4. **性能测试准确性**
   - 风险: 基准测试可能不够全面
   - 缓解: 多场景测试，使用 criterion 库

### 低风险

5. **向后兼容性**
   - 风险: 新 API 可能影响现有代码
   - 缓解: 现有 API 保持不变，新 API 独立
