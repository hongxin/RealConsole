**主题**: Shared Environment Variables in Task Execution（任务执行中的共享环境变量）

## 🎯 版本目标

解决任务执行系统的**环境变量隔离问题**，使同一 Stage 内的串行任务能够共享 shell 环境变量。

---

## 📊 问题回顾

### v1.19.0 发现的问题

虽然 v1.19.0 成功解决了任务输出显示问题，但用户实际测试时发现了更严重的问题：

```bash
# 用户测试 v1.19.0
/plan 先计算1加到100，然后再计算将刚才的所得结果与50相乘
/execute

# 输出（显示已修复，但计算错误）
✓ 3/3 · 100%

  ✓ 计算1到100的和
    1到100的和是: 5050        ← ✅ 正确

  ✓ 将和与50相乘
    最终结果是: 0             ← ❌ 错误！应该是 252500

  ✓ 验证计算结果
    实际结果:                 ← ❌ 空值！
```

### 根本原因

**代码位置**: `src/shell_executor.rs:216-218`

每个任务在独立的 shell 进程中执行，导致环境变量无法在任务间传递：

```rust
// v1.19.0 的问题
Command::new("/bin/sh")
    .arg("-c")
    .arg(&command_str)  // ← 每次都是新进程！
```

**执行流程**:
- Stage 1 (进程 A): `SUM=5050` → 进程退出 → 变量丢失
- Stage 2 (进程 B): `RESULT=$((SUM * 50))` → `$SUM` 不存在 → 结果为 `0`
- Stage 3 (进程 C): `echo $RESULT` → `$RESULT` 不存在 → 空输出

## ✅ 解决方案

### 核心修改

**修改文件**: `src/task/executor.rs`

**关键功能**:
1. **Stage 级别命令合并** - 同一 Stage 内的串行任务在同一 shell 会话中执行
2. **输出拆分机制** - 使用分隔符 `__REALCONSOLE_TASK_N_END__` 标记每个任务的输出边界
3. **智能错误定位** - 基于输出链断裂位置判断失败任务

### 实现细节

#### 1. 命令合并（`build_merged_command`）

```rust
fn build_merged_command(&self, tasks: &[SubTask]) -> String {
    let mut merged = String::new();

    for (idx, task) in tasks.iter().enumerate() {
        // 添加任务命令
        merged.push_str(&task.command);

        // 添加分隔符（用于输出拆分）
        merged.push_str(&format!(" ; echo '__REALCONSOLE_TASK_{}_END__'", idx));

        // 添加连接符（除了最后一个任务）
        if idx < tasks.len() - 1 {
            merged.push_str(" && ");
        }
    }

    merged
}
```

**生成的命令**:
```bash
SUM=$(seq 1 100 | awk '{sum+=$1} END {print sum}') && echo "1到100的和是: $SUM" ; echo '__REALCONSOLE_TASK_0_END__' && \
RESULT=$((SUM * 50)) && echo "最终结果是: $RESULT" ; echo '__REALCONSOLE_TASK_1_END__' && \
echo "验证: 5050 × 50 = 252500" ; echo '__REALCONSOLE_TASK_2_END__'
```

#### 2. 输出拆分（`split_merged_output`）

```rust
fn split_merged_output(&self, output: &str, task_count: usize) -> Vec<String> {
    let mut outputs = Vec::new();
    let mut current = String::new();

    for line in output.lines() {
        // 检查是否是分隔符
        if line.starts_with("__REALCONSOLE_TASK_") && line.ends_with("_END__") {
            outputs.push(current.trim_end().to_string());
            current.clear();
        } else {
            if !current.is_empty() {
                current.push('\n');
            }
            current.push_str(line);
        }
    }

    // 添加最后一个任务的输出
    if !current.is_empty() {
        outputs.push(current.trim_end().to_string());
    }

    // 确保返回的数组长度匹配任务数量
    while outputs.len() < task_count {
        outputs.push(String::new());
    }

    outputs
}
```

#### 3. 错误定位逻辑

```rust
// 判断此任务是否成功
let (status, error) = if !global_success {
    // 如果合并命令失败，判断是哪个任务失败
    // 策略：如果后续任务没有输出，说明当前任务失败导致链断裂
    let has_subsequent_output = (idx + 1..tasks.len())
        .any(|i| task_outputs.get(i).is_some_and(|s| !s.trim().is_empty()));

    if !has_subsequent_output {
        // 当前或之后的任务失败
        (TaskStatus::Failed, global_error.clone())
    } else {
        // 之前的任务已成功，当前任务也成功
        (TaskStatus::Success, None)
    }
} else {
    (TaskStatus::Success, None)
};
```

## 🔄 迭代修复历程

### 第一版：同一 Stage 内任务合并
- **问题**: 只合并同一 Stage 内的多个任务
- **限制**: LLM 生成的独立 Stage 之间仍然隔离

### 第二版：跨 Stage 串行任务合并
- **改进**: 合并所有串行 Stage 的任务
- **限制**: 只在所有 Stage 都是串行时才合并
- **问题**: 遇到并行 Stage 就不合并了

### 第三版：完全合并（最终版）
- **改进**: 只要有多个 Stage 就合并所有任务
- **权衡**: 并行 Stage 会串行执行（可接受）
