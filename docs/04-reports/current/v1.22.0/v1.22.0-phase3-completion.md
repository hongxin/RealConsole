### 4. Execute 方法应用配置

```rust
let total_tasks = plan.total_tasks();
let should_merge = self.merge_stages
    && plan.stages.len() > 1
    && total_tasks <= self.max_merged_tasks;

if should_merge {
    // 合并所有 Stage 的所有任务到一个命令中执行
    let all_tasks: Vec<SubTask> = plan
        .stages
        .iter()
        .flat_map(|s| s.tasks.clone())
        .collect();
    let results = self.execute_merged_tasks(&all_tasks).await?;
    all_results = results;
} else {
    // 逐阶段执行（原有逻辑）
    for (stage_idx, stage) in plan.stages.iter().enumerate() {
        ...
    }
}
```

**合并条件**（三个条件同时满足）：
1. `merge_stages` 配置启用
2. 多于 1 个 Stage（单 Stage 无需合并）
3. 总任务数 ≤ `max_merged_tasks`

```rust
// ✨ v1.22.0 Phase 3: 检查任务数是否超过限制
if stage.tasks.len() > self.max_merged_tasks {
    let mut results = Vec::new();
    for task in &stage.tasks {
        let result = self.execute_task(task).await;
        results.push(result);

        // 更新状态
        {
            let mut state = self.state.write().await;
            state.completed_tasks += 1;
        }
        self.report_progress().await;
    }
    return Ok(results);
}

// 多任务场景：合并执行以支持环境变量共享
self.execute_merged_tasks(&stage.tasks).await
```

**逻辑说明**：
- 如果单 Stage 任务数超过 `max_merged_tasks`，逐个执行
- 否则，合并执行以支持环境变量共享

## 🔧 技术亮点

### 1. 配置驱动的执行策略

**决策树**：
```
是否合并？
├─ merge_stages = false → 不合并
├─ stages.len() = 1 → 不合并（单 Stage）
├─ total_tasks > max_merged_tasks → 不合并（任务过多）
└─ 其他 → 合并执行
```

**示例场景**：
```yaml
# realconsole.yaml
task:
  execution:
    merge_stages: true        # 启用合并
    max_merged_tasks: 10      # 最多合并 10 个任务
```

```rust
// 场景 1: 5 个任务，少于限制 → 合并执行
// 场景 2: 15 个任务，超过限制 → 逐个执行
// 场景 3: merge_stages: false → 总是逐个执行
```

### 2. 构建器模式优雅设计

**链式调用**：
```rust
let executor = TaskExecutor::new(shell_executor)
    .with_merge_config(true, 10)   // 配置合并策略
    .with_timeout(60)               // 配置超时
    .with_progress_callback(cb);    // 配置回调
```

**优势**：
- 清晰的 API
- 可选参数灵活组合
- 类型安全

### 3. 向后兼容性保证

**默认行为**：
```rust
// v1.20.0 行为（环境变量共享）
merge_stages: true
max_merged_tasks: 20

// 用户无需修改配置即可升级
```

**迁移路径**：
```yaml

  execution:
    merge_stages: false
```

### 4. 错误处理与边界情况

**处理场景**：
- ✅ 0 个任务 → 正常返回空结果
- ✅ 1 个任务 → 直接执行（优化路径）
- ✅ 超过限制 → 逐个执行
- ✅ 单 Stage → 不触发跨 Stage 合并
- ✅ 并行任务 → 正确克隆配置

   - 防止命令行过长（系统限制）

3. **为什么使用构建器模式？**
