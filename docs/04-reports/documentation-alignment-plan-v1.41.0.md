**创建日期**: 2025-01-09
**当前版本**: v1.39.0 → v1.41.0（规整后目标版本）
**规整哲学**: 易变 · 极简 · 对齐

---

## 🎯 规整目标

### 核心原则

基于 RealConsole 的**易变哲学**和**极简主义**设计理念：

1. **对齐统一** - 所有文档版本号、日期、统计数据对齐到 v1.39.0
2. **适度简化** - 移除冗余内容，归档过时报告，保留核心价值
3. **易于演化** - 为 v1.x 收尾和 v2.0 演进做好准备
4. **保持质量** - 维护文档的准确性和实用性

### Phase 2: 报告文档归档（优先级：P0）

**目标**: 简化 04-reports，归档过时内容

#### 2.1 归档策略（基于易变哲学）

**三态归档法**:

1. **保留态** - 核心价值文档
   - 设计文档（trace-command-design.md 等）
   - 里程碑报告（v1.x-stabilization-and-release-plan.md）
   - 哲学思考（cyberpunk-theme-design.md 等）
   - v2.0 规划文档

2. **归档态** - 历史价值文档
   - 已完成功能的实施报告
   - 版本特定的完成报告（v1.28.0, v1.36.0 等）
   - 阶段性测试报告
   - 移动到 `04-reports/archives/v1.x/` 分类存放

3. **移除态** - 临时性文档
   - 重复的测试脚本报告
   - 过期的问题分析
   - 已合并到主文档的内容

#### 2.2 具体归档操作

**创建归档子目录**:
```bash
04-reports/archives/
├── v1.23-v1.30/  # Web Terminal 早期版本
├── v1.31-v1.35/  # Intent 系统优化
├── v1.36-v1.39/  # 最新功能（Cell Rerun、护眼配色）
└── legacy/       # v1.9.5 之前的报告
```

**移动规则**:
1. 以版本号命名的报告 → 对应版本目录
2. 功能特定报告 → 保留在 features/ 子目录
3. 技术类报告 → 保留在 technical/ 子目录
4. 一般性完成报告 → 归档到对应版本目录

**保留在根目录的文档** (< 20 个):

## 🎨 基于易变哲学的文档设计

### 文档三态

仿照 RealConsole 的"一分为三"哲学，文档也应有三态：

1. **核心态**（Core）- 00-core
   - 哲学思想、愿景、路线图
   - 稳定性高，变化少
   - 面向长期战略

2. **实践态**（Practice）- 02-practice
   - 用户指南、开发者文档
   - 稳定性中，随版本演化
   - 面向日常使用

3. **演化态**（Evolution）- 03-evolution + 04-reports
   - 版本历史、开发报告
   - 持续增长，定期归档
   - 面向历史追溯

### 文档极简主义

**原则**:
1. **一文一事** - 每个文档专注单一主题
2. **删繁就简** - 移除冗余和过时内容
3. **层次清晰** - 从概览到细节，逐层深入
4. **易于查找** - README 提供完整索引

**实践**:
- 根目录 README: 5-10 个核心链接
- 子目录 README: 完整索引 + 快速导航
- 单个文档: < 500 行（超过则拆分）
