## 二、实施细节

### 2.1 核心组件

#### QueryCache 结构

```rust
pub struct QueryCache {
    /// 搜索结果缓存：(query_hash, time_range) → Vec<MultimodalChunk>
    search_cache: LruCache<u64, CacheEntry<Vec<MultimodalChunk>>>,

    /// 上下文构建缓存：(task_hash, budget) → OptimizedMultimodalContext
    context_cache: LruCache<u64, CacheEntry<OptimizedMultimodalContext>>,

    /// TTL: 5 minutes（缓存过期时间）
    ttl: std::time::Duration,
}
```

**设计特点**：
- **容量限制**：Search 100条，Context 50条
- **TTL 过期**：5分钟自动失效
- **淘汰策略**：LRU（最近最少使用）
- **失效机制**：新数据写入时可清空

#### CacheEntry 封装

```rust
struct CacheEntry<T> {
    data: T,
    timestamp: std::time::Instant,
}

impl<T> CacheEntry<T> {
    fn is_expired(&self, ttl: std::time::Duration) -> bool {
        self.timestamp.elapsed() > ttl
    }
}
```

**特性**：
- 自动时间戳记录
- 过期检查支持

### 2.2 集成到 SmartWebUIOrchestrator

#### 内部可变性设计

```rust
pub struct SmartWebUIOrchestrator {
    perception: WebUIPerceptionLayer,
    understanding: WebUIUnderstandingLayer,
    orchestration: WebUIOrchestrationLayer,

    // ✨ 使用 Mutex 实现内部可变性
    cache: Mutex<QueryCache>,
}
```

**设计理由**：
- `orchestrator` 在 `websocket.rs` 中被 `Arc<T>` 包装
- 不能修改为 `Arc<RwLock<T>>`（影响整体设计）
- 仅 `cache` 需要可变性，其他层都是只读
- 使用 `Mutex<QueryCache>` 实现最小化改动

#### 缓存键生成

```rust
fn generate_cache_key<H: Hash>(params: H) -> u64 {
    let mut hasher = DefaultHasher::new();
    params.hash(&mut hasher);
    hasher.finish()
}
```

**使用示例**：
```rust
let cache_key = generate_cache_key((task, format!("{:?}", time_range)));
```

### 2.3 方法集成

#### extract_relevant_context (带缓存)

```rust
pub async fn extract_relevant_context(
    &self,
    task: &str,
    time_range: Option<TimeRange>,
    token_budget: usize,
) -> Result<OptimizedMultimodalContext> {
    // 1. 生成缓存键
    let cache_key = generate_cache_key((task, format!("{:?}", time_range)));

    // 2. 检查缓存
    let scored_chunks = {
        let cached_result = {
            let mut cache = self.cache.lock().await;
            cache.get_search_cached(cache_key)
        };

        if let Some(cached) = cached_result {
            eprintln!("[Memory 2.0] ✨ Using cached scored chunks");
            cached
        } else {
            // 缓存未命中，执行感知层 + 理解层
            eprintln!("[Memory 2.0] Cache miss, performing full perception + understanding");

            let chunks = self.perception.collect_multimodal_data(...).await?;
            let scored = self.understanding.score_relevance(task, chunks).await?;

            // 存入缓存
            {
                let mut cache = self.cache.lock().await;
                cache.put_search_cached(cache_key, scored.clone());
            }

            scored
        }
    };

    // 3. 编排层（不缓存，因为 token_budget 可能不同）
    let context = self.orchestration.build_optimized_context(scored_chunks, token_budget).await?;

    Ok(context)
}
```

**缓存策略**：
- ✅ 缓存：感知层 + 理解层结果（`scored_chunks`）
- ❌ 不缓存：编排层结果（因为 `token_budget` 可能不同）

### 4.2 解决的问题

#### 问题 1: `ContextMetadata` 未实现 `Clone`

**错误**：
```
error[E0277]: the trait bound `ContextMetadata: Clone` is not satisfied
```

**修复**：
```rust
// Before
#[derive(Debug, Serialize)]
pub struct ContextMetadata { ... }

// After
#[derive(Debug, Clone, Serialize)]
pub struct ContextMetadata { ... }
```

#### 问题 2: 方法签名冲突（`&mut self` vs `Arc<T>`）

**错误**：
```
error[E0596]: cannot borrow data in an `Arc` as mutable
  --> src/web/websocket.rs:1853:27
   |
1853 |  match orchestrator.quick_search(&subargs, 10).await {
     |        ^^^^^^^^^^^^ cannot borrow as mutable
```

**修复**：使用内部可变性
```rust
// Before
cache: QueryCache,              // 需要 &mut self
pub async fn extract_relevant_context(&mut self, ...) { ... }

// After
cache: Mutex<QueryCache>,       // 使用 Mutex 实现内部可变性
pub async fn extract_relevant_context(&self, ...) {
    let mut cache = self.cache.lock().await;  // 局部可变
    ...
}
```
