# 系统提示词功能优化路线图

**创建日期**: 2025-01-05
**状态**: 规划中（待用户测试验证）
**当前版本**: v1.39.0（基础功能已实现）

---

## 📋 已实现功能（v1.23.1）

### 核心能力
- ✅ 配置文件支持（`realconsole.yaml` 中的 `system_prompt` 字段）
- ✅ 运行时动态设置（`/set-prompt <prompt>`）
- ✅ 提示词查看（`/show-prompt`）
- ✅ 重置功能（`/set-prompt reset`）
- ✅ 三级优先级（运行时 > 配置 > 默认）

### 技术特性
- ✅ 动态生效（无需重启）
- ✅ 共享状态管理（`Arc<RwLock>`）
- ✅ 向后兼容
- ✅ 零警告编译
- ✅ 测试覆盖

### 当前限制
- ⚠️ 仅工具调用模式（WithTools）生效
- ⚠️ 运行时设置不持久化
- ⚠️ 无内置模板
- ⚠️ 无输入验证

#### 3. 基础验证

**目标**: 防止无效或有问题的提示词

**验证规则**:
```rust
pub fn validate_system_prompt(prompt: &str) -> Result<(), String> {
    // 1. 非空检查
    if prompt.trim().is_empty() {
        return Err("系统提示词不能为空".to_string());
    }

    // 2. 长度限制
    const MAX_LENGTH: usize = 4000;  // 根据 LLM 上下文窗口调整
    if prompt.len() > MAX_LENGTH {
        return Err(format!(
            "系统提示词过长（{} 字符），最大允许 {} 字符",
            prompt.len(),
            MAX_LENGTH
        ));
    }

    // 3. 字符检查（可选）
    // 检查是否包含控制字符等

    Ok(())
}
```

## 🤔 待讨论的设计问题

### 1. 持久化策略

**问题**: 运行时设置是否应该自动保存？

**选项**:
- A. 始终临时，重启丢失（当前实现）
- B. 明确保存标志（`--save`）
- C. 自动保存到临时文件
- D. 询问用户是否保存

**考虑因素**:
- 用户期望
- 配置文件的权威性
- 临时测试的便利性

---

### 2. 作用域控制

**问题**: 是否需要更细粒度的提示词控制？

**场景**:
```bash
# 全局提示词（默认）
/set-prompt "你是通用助手"

# 针对特定工具的提示词
/set-prompt --tool read_file "专注于文件分析"
/set-prompt --tool calculator "精确计算，解释步骤"

# 针对特定会话的提示词
/set-prompt --session "临时角色，本次会话有效"
```

**待验证**:
- 这种细粒度控制是否必要？
- 会不会增加复杂度？
- 用户能否理解作用域概念？

---

### 3. 变量替换时机

**问题**: 变量何时替换最合适？

**选项**:
- A. 设置时替换（静态）- 简单，但不够灵活
- B. 使用时替换（动态）- 灵活，但可能有性能开销
- C. 混合策略 - 某些变量静态，某些动态

**示例**:
```bash
# 选项 A: 设置时替换
/set-prompt "项目: {{project_name}}"
# 保存为: "项目: RealConsole"
# 切换项目后不会更新

# 选项 B: 使用时替换
/set-prompt "项目: {{project_name}}"
# 每次调用 LLM 时：
#   当前在 RealConsole → "项目: RealConsole"
#   切换到 OtherProject → "项目: OtherProject"
```
