## 🎨 设计哲学体现

### 一分为三

**类型维度**: Chart / Image / 未来扩展
```rust
trait MetadataExtractor {
    type Metadata;  // 抽象类型维度
}
```

**职责维度**: 提取 / 解析 / 验证
```rust
fn extract()    -> ExtractionResult  // 提取标记
fn parse()      -> Metadata          // 解析JSON
fn validate()   -> Result<()>        // 验证数据
```

**状态维度**: Success / Partial / Failure
```rust
struct ExtractionMetrics {
    found_primary_marker: bool,  // Partial
    json_parse_success: bool,    // Partial
    metadata: Option<T>,         // Success/Failure
}
```

### 极简主义

- **最小化重复**: 80% 重复代码消除
- **清晰抽象**: 单一 trait 覆盖所有场景
- **易于理解**: 通用算法一目了然

### 易变适应

- **零成本抽象**: Trait 编译期展开，无运行时开销
- **增量迁移**: 旧函数保留，新旧并存
- **监控驱动**: 指标反馈优化方向

## 💡 经验总结

### 成功因素

1. **设计先行**: 详细设计文档指导实施，避免返工
2. **测试驱动**: 先写测试，再写实现，质量有保障
3. **增量迁移**: 新旧并存，降低风险
4. **监控内建**: 从一开始就考虑可观测性

### 挑战与解决

| 挑战 | 解决方案 |
|------|----------|
| Trait Sized约束 | 添加 `where Self: Sized` |
| 错误类型不匹配 | `.map_err(\|e\| anyhow::anyhow!(e))` |
| JSON trailing content | 测试用例反映实际使用模式 |

### 关键洞察

1. **统一抽象的价值**
   - 一次投入（150行通用逻辑）
   - 长期受益（每个新类型仅20行）

2. **监控的重要性**
   - 详细指标加速调试
   - 性能数据驱动优化

3. **渐进式重构**
   - 保持向后兼容
   - 降低迁移风险
   - 允许回滚
