## 🚀 实施计划

### Phase 1: 快速测试诊断（30分钟）

**任务**:
1. 运行完整测试套件，记录所有失败的测试
2. 分析失败原因（环境问题 vs 代码问题）
3. 确定修复优先级

**输出**:
- 测试失败报告
- 修复优先级列表

### Phase 2: 修复库单元测试（2-3小时）

#### 2.1 修复 git_cmd 测试（优先级：高）

**问题分析**:
```bash
cargo test --lib git_cmd -- --nocapture
```

**可能原因**:
- Git 环境依赖问题
- 测试数据假设错误
- 输出格式变化

**修复策略**:
1. 隔离测试环境
2. Mock Git 命令输出
3. 增强错误信息

#### 2.2 修复 project_cmd 测试（优先级：高）

**问题分析**:
```bash
cargo test --lib project_cmd -- --nocapture
```

**可能原因**:
- 项目检测逻辑依赖当前目录
- 建议系统状态问题
- Git 信息获取失败

**修复策略**:
1. 使用临时测试目录
2. Mock 文件系统状态
3. 解耦外部依赖

#### 2.3 修复 context_suggester 测试（优先级：中）

**问题分析**:
```bash
cargo test --lib context_suggester -- --nocapture
```

**可能原因**:
- 上下文检测逻辑错误
- Rust 项目标志文件缺失
- 建议生成逻辑变化

**修复策略**:
1. 明确测试前置条件
2. 增强项目检测鲁棒性
3. 添加更多测试用例

### Phase 3: 清理编译警告（1小时）

#### 3.1 Agent.rs 弃用警告（6个）

**当前代码**:
```rust
let memory = agent.memory();  // deprecated
let logger = agent.exec_logger();  // deprecated
```

**修复为**:
```rust
let memory = agent.state_manager().memory();
let logger = agent.state_manager().exec_logger();
```

**影响文件**:
- `src/agent.rs`
- 可能的其他调用点

#### 3.2 tracker.rs 未使用 mut（6个）

**修复策略**:
- 移除不必要的 `mut` 关键字
- 或者添加 `_` 前缀表示未使用

#### 3.3 furnace.rs 无用比较（1个）

**问题代码**:
```rust
if some_u64_value >= 0 {  // 总是为真
    // ...
}
```

**修复策略**:
- 移除无用的比较
- 或者修改为有意义的检查

## 🚧 风险与缓解

### 风险 1: 测试修复复杂度超预期

**影响**: 延迟发布
**概率**: 中
**缓解**:
- 优先修复高价值测试
- 对于复杂测试，添加 `#[ignore]` 注释，后续修复
- 保持每个测试独立可测

### 风险 2: 编译警告涉及 API 重构

**影响**: 引入新 bug
**概率**: 低
**缓解**:
- 仅做最小化修改
- 每个修改后运行完整测试
- 保留 deprecated API 向后兼容

### 风险 3: 文档更新遗漏

**影响**: 文档不一致
**概率**: 低
**缓解**:
- 使用 checklist 确保完整性
- 交叉检查版本号
- 自动化版本号同步（未来改进）
