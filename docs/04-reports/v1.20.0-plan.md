## 🎯 核心目标

解决任务执行系统的**环境变量隔离问题**，使同一 Stage 内的串行任务能够共享 shell 环境变量。

---

## 📊 问题背景

### 问题描述

当前任务执行系统中，每个任务在独立的 shell 进程中执行，导致 shell 环境变量无法在任务间传递。

### 问题案例

```bash
# 用户输入
/plan 先计算1加到100，然后再计算将刚才的所得结果与50相乘

# 生成的计划
▸ 3 阶段 · 3 任务
├─ Stage 1: SUM=$(seq 1 100 | awk '{sum+=$1} END {print sum}') && echo "1到100的和是: $SUM"
├─ Stage 2: RESULT=$((SUM * 50)) && echo "最终结果是: $RESULT"
└─ Stage 3: echo "验证: $RESULT"

# ❌ v1.19.0 执行结果（问题）
✓ 3/3 · 100%

  ✓ 计算1到100的和
    1到100的和是: 5050        ← ✅ 正确

  ✓ 将和与50相乘
    最终结果是: 0             ← ❌ 错误！SUM 变量丢失

  ✓ 验证计算结果
    实际结果:                 ← ❌ 空值！RESULT 变量丢失
```

### 根本原因

**代码位置**: `src/shell_executor.rs:216-218`

```rust
// 每个任务在独立的进程中执行
Command::new("/bin/sh")
    .arg("-c")
    .arg(&command_str)  // ← 每次都是新进程！
```

**执行流程**:
1. **Stage 1**: 进程 A 执行 `SUM=5050` → 进程 A 退出 → `SUM` 丢失
2. **Stage 2**: 进程 B 执行 `RESULT=$((SUM * 50))` → `$SUM` 不存在 → `0`
3. **Stage 3**: 进程 C 执行 `echo $RESULT` → `$RESULT` 不存在 → 空

**影响范围**:
- 所有依赖环境变量传递的多阶段任务
- 数据处理工作流（计算 → 存储 → 验证）
- 构建流程（配置 → 编译 → 测试）

## 🔧 解决方案

### 方案 A: Stage 级别命令合并（推荐）⭐

**核心思想**: 同一 Stage 内的**串行任务**在同一 shell 会话中执行

**实现原理**:

```rust
// === 修改前（v1.19.0）：每个任务独立执行 ===
async fn execute_stage_sequential(tasks: &[SubTask]) -> Vec<TaskResult> {
    let mut results = Vec::new();
    for task in tasks {
        // 每个任务都是新进程
        let result = execute_command(&task.command).await;  // ← 独立进程
        results.push(result);
    }
    results
}

// === 修改后（v1.20.0）：Stage 内任务合并执行 ===
async fn execute_stage_sequential(tasks: &[SubTask]) -> Vec<TaskResult> {
    // 1. 合并命令（使用 && 连接）
    let merged_command = tasks
        .iter()
        .map(|t| &t.command)
        .collect::<Vec<_>>()
        .join(" && ");

    // 2. 在同一进程中执行
    let output = execute_command(&merged_command).await;  // ← 同一进程！

    // 3. 拆分输出（按任务）
    split_output_by_tasks(output, tasks)
}
```

**优势**:
- ✅ 完全解决环境变量共享问题
- ✅ 符合 shell 脚本的直觉（`cmd1 && cmd2 && cmd3`）
- ✅ 保持错误处理语义（任一命令失败则停止）
- ✅ 实现简单，风险可控

**挑战**:
- ⚠️ 输出拆分（需要识别每个任务的输出边界）
- ⚠️ 错误定位（需要知道哪个任务失败）
- ⚠️ 进度报告（合并后无法实时反馈单任务进度）

### 方案 B: 持久化 Shell 会话

**核心思想**: 维护一个长期运行的 shell 进程，通过管道交互

**实现原理**:

```rust
// 启动持久化 shell
let mut shell = Command::new("/bin/sh")
    .stdin(Stdio::piped())
    .stdout(Stdio::piped())
    .spawn()?;

// 逐条发送命令
for task in tasks {
    writeln!(shell.stdin, "{}", task.command)?;
    let output = read_until_prompt(shell.stdout)?;
}
```

**优势**:
- ✅ 完美支持环境变量共享
- ✅ 支持 `cd` 等状态改变命令
- ✅ 可以实时获取每个任务的输出

**劣势**:
- ❌ 实现复杂（需要处理 prompt、EOF、信号等）
- ❌ 错误处理困难（shell 崩溃如何恢复）
- ❌ 跨平台兼容性差（Windows cmd 行为不同）

---

### 方案 C: 显式状态传递

**核心思想**: LLM 生成任务时，显式传递变量（不依赖 shell 环境）

**示例**:

```bash
# 修改前（依赖环境变量）
Stage 1: SUM=$(seq 1 100 | awk '{sum+=$1} END {print sum}')
Stage 2: RESULT=$((SUM * 50))  ← 依赖 $SUM

# 修改后（显式传递）
Stage 1: seq 1 100 | awk '{sum+=$1} END {print sum}' > /tmp/sum.txt
Stage 2: RESULT=$(($(cat /tmp/sum.txt) * 50))  ← 从文件读取
```

**优势**:
- ✅ 不需要修改执行器
- ✅ 结果可审计（中间状态保存在文件）

**劣势**:
- ❌ 依赖 LLM 正确生成（不可靠）
- ❌ 需要管理临时文件（清理、权限）
- ❌ 用户体验差（增加复杂度）

## ✅ 最终选择：方案 A（Stage 级别命令合并）

**综合方案**:
1. **核心修改**: 实现 Stage 级别命令合并
2. **输出拆分**: 使用标记分隔符（`echo "===TASK_1_END==="`）
3. **错误定位**: 记录每个任务的退出码
4. **向后兼容**: 仅对串行 Stage 应用合并

## 📌 技术细节

### 命令合并实现

```rust
/// 合并串行任务的命令
fn merge_sequential_commands(tasks: &[SubTask]) -> String {
    let mut merged = String::new();

    for (idx, task) in tasks.iter().enumerate() {
        // 添加任务命令
        merged.push_str(&task.command);

        // 添加分隔符（用于输出拆分）
        merged.push_str(&format!(" && echo '===TASK_{}_END===' ", idx));

        // 添加连接符（除了最后一个任务）
        if idx < tasks.len() - 1 {
            merged.push_str(" && ");
        }
    }

    merged
}
```

### 输出拆分实现

```rust
/// 拆分合并后的输出
fn split_merged_output(output: &str, task_count: usize) -> Vec<String> {
    let mut outputs = Vec::new();
    let mut current = String::new();

    for line in output.lines() {
        if line.starts_with("===TASK_") && line.ends_with("_END===") {
            outputs.push(current.clone());
            current.clear();
        } else {
            current.push_str(line);
            current.push('\n');
        }
    }

    outputs
}
```
