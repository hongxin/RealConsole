### Phase 2: 数字高亮 (P2)

**实施时间**: ~1.25 小时
**测试覆盖**: 11 tests (增加 5 个新测试)

**核心功能**：
```rust
/// 高亮文本中的数字（极简设计）
pub fn highlight_numbers(text: &str) -> String {
    static NUMBER_RE: Lazy<Regex> =
        Lazy::new(|| Regex::new(r"\b(\d+(?:\.\d+)?)\b").unwrap());

    NUMBER_RE.replace_all(text, |caps: &regex::Captures| {
        format!("{}", caps[1].cyan())  // cyan，不加粗
    }).to_string()
}
```

**设计原则**：
- **极简配色**: cyan（与标题一致）而非 yellow
- **微妙突出**: 不加粗，优雅呈现
- **性能优化**: `once_cell::Lazy` 缓存正则表达式（~10-20x 提升）
- **智能匹配**: 单词边界，支持整数、小数、百分比、带单位数字

**应用范围**：
- Standard 模式（任务输出）
- Debug 模式（详细输出）
- 通过 `config.task.display.highlight_numbers` 控制

**视觉效果**：
```
Found 42 items in 3 seconds
Success rate: 98.5%
Downloaded 10GB in 50ms

→ 数字 42, 3, 98.5, 10, 50 显示为 cyan
→ 其他文本显示为 dimmed（灰色）
```

### Phase 3: 执行器配置 (P2)

**实施时间**: ~1.75 小时
**测试覆盖**: 29 tests (增加 6 个新测试)

**核心功能**：
```rust
pub struct TaskExecutor {
    // ...
    /// 是否合并 Stage 执行（支持环境变量共享）
    merge_stages: bool,

    /// 合并执行的最大任务数（防止命令过长）
    max_merged_tasks: usize,
}

impl TaskExecutor {
    pub fn with_merge_config(mut self, merge_stages: bool, max_merged_tasks: usize) -> Self {
        self.merge_stages = merge_stages;
        self.max_merged_tasks = max_merged_tasks;
        self
    }
}
```

**配置项**：
```yaml
# realconsole.yaml
task:
  execution:
    merge_stages: true        # 默认启用合并（环境变量共享）
    max_merged_tasks: 20      # 默认最大 20 个任务
```

**执行策略决策树**：
```
是否合并？
├─ merge_stages = false → 不合并
├─ stages.len() = 1 → 不合并（单 Stage）
├─ total_tasks > max_merged_tasks → 不合并（任务过多）
└─ 其他 → 合并执行
```

**使用场景**：
```yaml
# 场景 1: 默认配置（推荐）
task:
  execution:
    merge_stages: true
    max_merged_tasks: 20

# 场景 2: 禁用合并（调试模式）
task:
  execution:
    merge_stages: false

# 场景 3: 小批量合并
task:
  execution:
    merge_stages: true
    max_merged_tasks: 5
```

## 💡 经验总结

### 成功要素

1. **阶段化开发**: 三个独立阶段，逐个完成，降低复杂度
2. **测试驱动**: 每个阶段都有完整测试，发现问题及时修复
3. **极简主义**: Phase 2 的配色决策体现了对美学的追求
4. **用户导向**: 友好的命令输出和错误提示
5. **完整文档**: 每个阶段都有详细的完成报告

### 技术发现

1. **Serde 链式依赖**: 嵌套结构需要所有类型都实现序列化
2. **once_cell 性能**: 静态初始化的零成本抽象
3. **构建器模式**: 流畅 API 提升用户体验
4. **配置驱动**: 灵活性与简洁性的平衡

### 设计决策

**为什么用 JSON 而非二进制格式？**
- 可读性好，易于调试
- 跨平台兼容
- 未来易于迁移

**为什么默认启用合并？**
- 保持 v1.20.0 的环境变量共享特性
- 性能优化（减少 shell 进程）
- 用户无需配置即可享受

**为什么限制 20 个任务？**
- 防止命令行过长
- 合理的批处理大小
- 可通过配置调整
