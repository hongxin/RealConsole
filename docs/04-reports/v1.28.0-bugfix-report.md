## Bug 1: 状态图标显示 `?`

### 问题描述

用户反馈回合卡片的状态图标显示为 `?`，而不是预期的图标：
- ✓ (Success)
- ⏳ (Running)
- ✗ (Error)
- ⏸ (Pending)

### 根本原因

**Rust enum 序列化格式不一致**：

在 `src/web/session.rs` 中定义的 `RoundStatus` enum：

```rust
#[derive(Debug, Clone, Serialize, Deserialize)]
#[serde(rename_all = "lowercase")]
pub enum RoundStatus {
    Pending,    // 无字段
    Running,    // 无字段
    Success,    // 无字段
    Error { message: String },  // 有字段
}
```

serde 的序列化行为：
- **无字段的 variant** (Pending, Running, Success) 序列化为**字符串**:
  ```json
  "pending", "running", "success"
  ```

- **有字段的 variant** (Error) 序列化为**对象**:
  ```json
  {"error": {"message": "..."}}
  ```

JavaScript 的 `getStatusIcon()` 方法只处理字符串，导致对象格式的 `Error` 返回 `?`：

```javascript
getStatusIcon(status) {
    const icons = {
        success: '✓',
        running: '⏳',
        error: '✗',
        pending: '⏸'
    };
    return icons[status] || '?';  // status 是对象时返回 '?'
}
```

### 修复方案

**添加状态标准化方法** (`src/web/server.rs`):

```javascript
// 标准化状态值（处理 Rust enum 序列化格式）
normalizeStatus(status) {
    // 如果是字符串，直接返回（pending, running, success）
    if (typeof status === 'string') {
        return status;
    }
    // 如果是对象，提取键名（error）
    if (typeof status === 'object' && status !== null) {
        return Object.keys(status)[0] || 'unknown';
    }
    return 'unknown';
}
```

**在所有使用 status 的地方应用标准化**:

1. `createRound()` - 创建回合时：
   ```javascript
   status: this.normalizeStatus(round.status),
   ```

2. `updateRoundStatus()` - 更新状态时：
   ```javascript
   const normalizedStatus = this.normalizeStatus(status);
   ```

3. `completeRound()` - 完成回合时：
   ```javascript
   const normalizedStatus = this.normalizeStatus(roundData.status);
   ```

### 修复文件

- `src/web/server.rs` (+13 行，修改 3 处)

### 测试验证

修复后，状态图标应正确显示：
- `"pending"` → ⏸
- `"running"` → ⏳
- `"success"` → ✓
- `{"error": {"message": "..."}}` → ✗

## Bug 2: 输入输出格式不正确

### 问题描述

回合卡片的输入输出部分 HTML 结构与 CSS 样式定义不匹配，导致：
- 缺少标签（"📥 Input:", "📤 Output:"）
- 没有样式化的内容容器
- 边框、背景色等样式未应用

### 根本原因

**HTML 结构与 CSS 不匹配**：

**CSS 定义** (`src/web/server.rs` 1920-1970 行):
```css
.round-input-label {
    display: block;
    color: #00f0ff;
    font-size: 0.85em;
    font-weight: 600;
}

.round-input-content {
    padding: 8px 12px;
    background: rgba(0, 240, 255, 0.05);
    border-left: 3px solid #00f0ff;
    /* ... */
}
```

**原 HTML 实现** (错误):
```javascript
inputDiv.innerHTML = `
    <span class="prompt">% </span>
    <span class="input-text">${this.escapeHtml(round.userInput)}</span>
`;
```

问题：
1. 使用了 `class="prompt"` 和 `class="input-text"`，但 CSS 中没有这些类
2. 缺少 `round-input-label` 和 `round-input-content`
3. 没有标签文字

### 修复方案

**更新 HTML 结构匹配 CSS** (`src/web/server.rs`):

**修复后的输入部分**:
```javascript
inputDiv.innerHTML = `
    <span class="round-input-label">📥 Input:</span>
    <div class="round-input-content">${this.escapeHtml(round.userInput)}</div>
`;
```

**修复后的输出部分**:
```javascript
outputDiv.innerHTML = `
    <span class="round-output-label">📤 Output:</span>
    <div class="output-content"></div>
`;
```

## 非 Bug: 时间显示 0.00s

### 问题描述

用户反馈执行时间显示为 `0.00s`。

### 分析

**这不是 bug**，而是配置问题：

1. **API Key 无效**：使用的是测试 Key `"test-key"`，不是真实的 Deepseek API Key
2. **LLM 未执行**：API 认证失败后，LLM 没有执行，因此：
   - `execution_time` 保持初始值 `0.0`
   - `complete_round()` 没有被调用（因为进入错误分支）
   - 回合状态应该是 `Error`

### 解决方案

**用户需要配置真实的 API Key**:

```bash
# 方式 1: 环境变量
export DEEPSEEK_API_KEY="sk-your-real-api-key-here"
./target/release/realconsole web

# 方式 2: .env 文件
echo 'DEEPSEEK_API_KEY="sk-your-real-api-key-here"' > .env
./target/release/realconsole web

# 方式 3: 配置文件
realconsole wizard
```

### 预期行为

配置真实 API Key 后：
- 对话能正常执行
- 执行时间显示为实际值（如 `1.23s`, `2.45s`）
- 回合状态为 `Success` (✓)
- 工具使用正确追踪

## 学习与改进

### 经验教训

1. **跨语言序列化需要注意格式差异**
   - Rust enum 的序列化格式取决于 variant 是否有字段
   - JavaScript 需要处理多种数据格式（字符串、对象）

2. **HTML/CSS 实现需要保持一致**
   - 先设计 CSS，然后严格按照 class 名称编写 HTML
   - 或先写 HTML，然后为实际使用的 class 编写 CSS

3. **测试需要使用真实环境**
   - 模拟数据（如 "test-key"）可能掩盖问题
   - 关键路径测试需要真实配置

### 未来改进

1. **类型安全的序列化**：

     | { error: { message: string } };
