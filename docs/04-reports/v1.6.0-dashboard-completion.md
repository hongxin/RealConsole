## 一、功能概述

v1.6.0 实现了基于易经"四象"哲学的系统 Dashboard，提供统一的系统健康度视图和智能建议系统。

### 核心特性

1. **系统健康度评分**（0-100 分）
   - 命令成功率（40% 权重）
   - LLM 响应质量（20% 权重）
   - 系统活跃度（20% 权重）
   - 异常程度（20% 权重，反向）

2. **四象分区视图**
   - ☰ 太阳（Statistics）- 命令频率、使用模式
   - ☷ 太阴（Memory）- 对话上下文、知识积累
   - ☲ 少阳（Coordination）- 执行追踪、协同流程
   - ☵ 少阴（BlackBox）- LLM 调用、智能黑盒

3. **异常检测系统**
   - 高失败率检测（>20% 触发）
   - 严重程度分级（1-5）
   - 数据关联（失败率、失败次数等）

4. **智能建议系统**
   - 基于健康度的建议
   - 基于成功率的建议
   - 基于异常的建议
   - 基于活跃度的建议
   - 优先级排序（1-5）

### 核心类型

```rust
/// Dashboard 配置
pub struct DashboardConfig {
    pub four_quadrants: bool,      // 是否启用四象分区
    pub show_health_score: bool,   // 是否显示健康度
    pub show_anomalies: bool,      // 是否显示异常
    pub show_suggestions: bool,    // 是否显示建议
    pub time_window_hours: usize,  // 时间窗口
}

/// 系统健康度评分
pub struct HealthScore {
    pub overall: u8,           // 总体评分 (0-100)
    pub success_rate: u8,      // 命令成功率
    pub llm_quality: u8,       // LLM 响应质量
    pub activity_level: u8,    // 系统活跃度
    pub anomaly_score: u8,     // 异常程度
}

/// 异常类型
pub enum AnomalyType {
    HighFailureRate,       // 高失败率
    SlowLlmResponse,       // LLM 响应慢
    RepeatedErrors,        // 重复错误
    UnusualPattern,        // 异常模式
    ResourceAnomaly,       // 资源异常
}

/// 智能建议
pub struct Suggestion {
    pub category: String,      // 建议类型
    pub message: String,       // 建议内容
    pub priority: u8,          // 优先级 (1-5)
    pub command: Option<String>, // 可执行命令
}
```

### 健康度计算算法

```rust
// 加权平均算法
overall = (success_rate * 0.4)
        + (llm_quality * 0.2)
        + (activity_level * 0.2)
        + ((100 - anomaly_score) * 0.2)

// 健康等级分级
90-100: 优秀 (绿色)
75-89:  良好 (青色)
60-74:  一般 (黄色)
40-59:  较差 (品红)
0-39:   危险 (红色)
```

## 八、开发心得

### 离坎二卦的实践

在实现 Dashboard 的过程中，深刻体会到了离坎二卦所代表的"智能自驱力"：

**离卦（向外照明）**：
- Dashboard 不仅仅是数据的展示，更是对用户需求的主动响应
- 通过视觉化、彩色化，让复杂的系统状态一目了然
- 智能建议提供了"下一步行动"的指引

**坎卦（向内深入）**：
- 健康度算法深入分析系统的多个维度
- 异常检测挖掘隐藏的系统问题
- 建议生成基于规律的智能推理

### 四象哲学的落地

四象分区不是简单的四格划分，而是对系统观测维度的深层理解：
- **太阳（Statistics）**：外显的命令执行，最容易观测
- **太阴（Memory）**：内隐的上下文记忆，最难以捕捉
- **少阳（Coordination）**：阳中带阴，执行中的协同
- **少阴（BlackBox）**：阴中带阳，黑盒中的智能

这种分类方式比传统的"前端/后端/数据库/网络"更加贴近智能系统的本质。

### 消息卦的演化

Dashboard 本身就是一个"消息卦"的体现：
- 当系统健康度下降，异常增多（阳消阴长）
- 当用户采取建议，问题解决（阴消阳长）
- Dashboard 展示了这种动态的演化过程

这种动态视角，比静态的"快照"更有价值。
