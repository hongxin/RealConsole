```rust
/// ✨ v1.6.0: 获取失败的执行日志
///
/// 用于异常检测和错误分析
pub async fn get_failed_logs(&self, limit: usize) -> Result<Vec<ExecutionLog>> {
    let logger = self.exec_logger.read().await;
    let recent_logs = logger.recent(limit * 2); // 获取更多日志，然后过滤失败的

    Ok(recent_logs
        .into_iter()
        .filter(|log| !log.success)
        .take(limit)
        .cloned()
        .collect())
}
```

**设计要点**：
- 获取 `limit * 2` 条日志，确保有足够的失败日志样本
- 通过 `filter()` 过滤出失败的日志
- 返回克隆的日志列表，避免持有锁

### 2. 重复错误检测算法

**文件**: `src/tracer/dashboard.rs`

在 `detect_anomalies()` 方法中添加了重复错误检测：

```rust
// 2. 检测重复错误
if let Ok(failed_logs) = self.tracer.get_failed_logs(50).await {
    // 统计错误消息出现次数
    let mut error_counts: HashMap<String, usize> = HashMap::new();
    for log in &failed_logs {
        let error_key = log.result_preview.clone();
        *error_counts.entry(error_key).or_insert(0) += 1;
    }

    // 找出重复次数 >= 3 的错误
    let repeated_errors: Vec<_> = error_counts
        .iter()
        .filter(|(_, &count)| count >= 3)
        .collect();

    if !repeated_errors.is_empty() {
        // 找出最严重的重复错误
        let max_count = repeated_errors.iter().map(|(_, &count)| count).max().unwrap_or(0);
        let most_repeated = repeated_errors
            .iter()
            .find(|(_, &count)| count == max_count)
            .map(|(msg, _)| msg.as_str())
            .unwrap_or("未知错误");

        let mut data = HashMap::new();
        data.insert("error_count".to_string(), max_count.to_string());
        data.insert("unique_errors".to_string(), repeated_errors.len().to_string());
        data.insert("top_error".to_string(), most_repeated.to_string());

        anomalies.push(Anomaly {
            anomaly_type: AnomalyType::RepeatedErrors,
            description: format!("检测到重复错误：{} 次 - {}", max_count,
                if most_repeated.len() > 40 {
                    format!("{}...", &most_repeated[..40])
                } else {
                    most_repeated.to_string()
                }
            ),
            severity: if max_count >= 5 { 5 } else { 4 },
            data,
        });
    }
}
```

**算法要点**：
- 使用 `HashMap` 统计每个错误消息的出现次数
- 阈值设定为 **3 次**（平衡灵敏度和噪声）
- 提取最严重的重复错误作为代表
- 错误消息超过 40 字符时自动截断
- 严重程度：重复 >= 5 次为级别 5，否则为级别 4

## 七、开发心得

### 算法选择的权衡

在设计重复错误检测时，面临几个选择：

1. **阈值设定**：选择 3 次作为阈值
   - 太低（如 2 次）：可能产生过多误报
   - 太高（如 5 次）：可能错过一些重要模式
   - 3 次是一个平衡点，既能捕捉真实模式，又不会过于敏感

2. **窗口大小**：选择最近 50 条失败日志
   - 太小：可能遗漏历史重复错误
   - 太大：可能包含过时的错误
   - 50 条覆盖了大部分使用场景

3. **错误匹配**：使用精确匹配
   - 简单高效，性能好
   - 未来可扩展为模糊匹配或语义匹配

### 坎卦智慧的实践

在实现过程中，深刻体会到"坎卦"代表的"向内深入"智慧：

1. **不满足于表面**：不仅看失败率数字，还要分析失败的模式
2. **洞察隐藏规律**：通过统计分析，发现人眼难以察觉的重复模式
3. **提供深层价值**：帮助用户发现根本问题，而非只是症状

这种"向内深入"的能力，是智能系统区别于简单工具的关键。
