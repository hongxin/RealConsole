## 📊 概览

## 🚨 高优先级（v1.18.0 处理）

### 1. Clippy 警告清理

**数量**: 18 个
**影响**: 代码质量、可维护性
**预估工作量**: 2-3 小时

#### 详细清单

| 序号 | 类型 | 位置 | 说明 | 建议修复方案 |
|------|------|------|------|--------------|
| 1 | too_many_arguments | src/llm/logger.rs:239 | log_interaction() 有 9 个参数 | 封装为结构体 LogRequest |
| 2-3 | redundant_closure | src/shell_executor.rs:525,583 | 冗余闭包 | 使用函数指针 RiskAssessment::safe |
| 4-5 | module_inception | src/wizard/mod.rs | 模块名重复 | 重命名内部模块或外部模块 |
| 6-8 | format_in_format_args | 多处 | format! 嵌套 | 提取为临时变量 |
| 9 | unused_loop_counter | - | 循环计数器未使用 | 使用 enumerate() 或移除 |
| 10 | field_assignment_outside_initializer | - | 字段赋值在构造器外 | 使用结构体更新语法 |
| 11-15 | useless_format | 多处 | 空格式字符串 | 直接使用 .to_string() |
| 16 | only_used_in_recursion | - | 参数仅用于递归 | 重构递归逻辑 |
| 17 | type_complexity | - | 复杂类型 | 定义 type alias |
| 18 | method_name_collision | - | 方法名与标准库冲突 | 重命名方法 |

**优先级**: 🔴 高
**建议**: v1.18.0 统一处理

## ⚠️ 中优先级（v1.19.0 或 v2.0.0）

### 2. 测试覆盖缺口

**影响**: 测试可靠性

| 模块 | 忽略测试数 | 原因 | 建议 |
|------|-----------|------|------|
| voice::platform | 2 | 需要系统 TTS | Mock 或集成测试环境 |
| wizard::validator | 部分 | 需要外部服务 | Docker compose 测试环境 |
| llm::ollama | 部分 | 需要 Ollama 服务 | Mock HTTP 或 Docker |

**优先级**: 🟡 中
**建议**: 考虑 Docker Compose 测试环境

### 3. 文档不一致

**影响**: 用户体验

- README.md vs README.cn.md 可能存在更新不同步
- 部分新功能（Phase 5 索引）未在用户手册中体现
- API 文档需要生成（cargo doc）

**优先级**: 🟡 中
**建议**: v1.17.0 发布前更新

### 4. 性能基准测试不完整

**当前状态**:
- ✅ 查询性能测试（Phase 5）
- ⏸️ 端到端性能测试
- ⏸️ 大规模数据性能测试（10k+）
- ⏸️ 并发性能测试

**优先级**: 🟡 中
**建议**: v1.18.0 补充

## 🔵 低优先级（v2.0.0 考虑）

### 5. 架构改进机会

#### 5.1 索引覆盖范围

**现状**: 索引仅覆盖 custom_entries
**机会**: 扩展到 History, ExecutionLogger, Context

**影响**: 性能提升空间
**优先级**: 🔵 低（v2.0.0）

#### 5.2 异步运行时优化

**现状**: tokio 默认配置
**机会**:
- worker 线程数优化
- 任务调度优化
- 资源池化

**影响**: 并发性能
**优先级**: 🔵 低（v2.0.0）

#### 5.3 序列化性能

**现状**: serde_json, serde_yml
**机会**: 考虑更快的序列化库（如 bincode）

**影响**: I/O 性能
**优先级**: 🔵 低（v2.0.0）

### 6. 依赖更新

**现状**: 部分依赖可能有更新版本
**建议**: 定期执行 `cargo outdated` 检查

**优先级**: 🔵 低
**频率**: 每个 minor 版本

## 📝 债务管理原则

### 1. 零容忍原则

- ❌ **不接受新增 Clippy 警告**（在 CI 中强制）
- ❌ **不接受测试通过率下降**
- ❌ **不接受已知 bug 遗留**

### 2. 渐进式改善

- ✅ 每个版本清理部分债务
- ✅ 优先级驱动（高 → 中 → 低）
- ✅ 小步快跑，持续改进

### 3. 预防为主

- ✅ Code Review 关注质量
- ✅ PR 必须通过 Clippy
- ✅ 测试覆盖率要求
