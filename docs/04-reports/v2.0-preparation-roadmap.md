## 战略定位

### v2.0 愿景
从 **"增强型 CLI 工具"** 演进为 **"AI 智能开发伴侣"**

三大转变维度：
1. **工具 → 伴侣**: 从被动命令执行到主动协作
2. **执行 → 理解**: 从"知道怎么做"到"知道为什么"
3. **静态 → 演化**: 从固定规则到学习和自我优化

### 准备工作核心目标

| 阶段 | 版本范围 | 目标 | 时间 |

```rust
struct SuggestionEngine {
    // 三源融合
    frequency_model: FrequencyModel,    // 历史频率
    semantic_model: SemanticModel,      // LLM 语义理解
    context_model: ContextModel,        // 上下文感知
}

impl SuggestionEngine {
    async fn suggest(&self, input: &str, ctx: &Context) -> Vec<Suggestion> {
        let freq_suggestions = self.frequency_model.suggest(input);
        let semantic_suggestions = self.semantic_model.suggest(input, ctx).await;
        let context_suggestions = self.context_model.suggest(ctx);

        self.merge_and_rank(freq_suggestions, semantic_suggestions, context_suggestions)
    }
}
```

## 关键技术决策点

### 需要在探路期确定的决策

1. **插件隔离方案**
   - 选项 A: 原生动态库 (libloading) - 高性能，低隔离
   - 选项 B: WASM 沙箱 (wasmtime) - 中性能，高隔离
   - 选项 C: 进程隔离 - 低性能，最高隔离
   - **决策时间**: v1.61.0 后

2. **存储后端选择**
   - 选项 A: 纯文件系统 - 简单，无依赖
   - 选项 B: SQLite - 成熟，事务支持
   - 选项 C: sled/rocksdb - 高性能，复杂
   - **决策时间**: v1.59.0 后

3. **向量检索方案**
   - 选项 A: 内存向量 (usearch) - 简单，适合小规模
   - 选项 B: Qdrant/Milvus - 专业，需要外部服务
   - 选项 C: 自建索引 (HNSW) - 可控，开发成本高
   - **决策时间**: v1.64.0 后

4. **LLM 路由策略**
   - 选项 A: 规则路由 - 简单，可预测
   - 选项 B: ML 路由 - 智能，需要训练
   - 选项 C: 混合路由 - 平衡，复杂度中等
   - **决策时间**: v1.63.0 后
