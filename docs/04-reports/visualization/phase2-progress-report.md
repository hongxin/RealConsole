### 6. 回合卡片集成与视觉优化 ✅

**回合卡片集成修复** (`src/web/frontend.rs:2837-2875`)：
- **问题**：图表初始渲染在回合卡片外部，无法随卡片折叠/展开
- **解决**：使用 querySelector 定位到 `[data-round-id]` 的 `.output-content` 区域
- **效果**：图表完整嵌入回合对话，支持折叠/展开交互

**CSS 视觉优化** (`src/web/frontend.rs:7367-7446`)：

## 架构亮点

### 1. 模块化设计 🏗️

```
visualization/
├── types.rs      # 数据模型（支持 4 种图表）
├── parser.rs     # 命令解析（折线/柱状/饼图/散点）
├── csv.rs        # CSV 文件解析
└── mod.rs        # 模块导出
```

### 2. 类型安全 🛡️

- **ChartType**：Copy trait，避免所有权问题
- **Series**：普通数据 vs 散点数据分离（`data` vs `points`）
- **验证**：多层次验证（解析层、数据层、执行层）

### 3. 错误处理 📋

**友好的错误提示**:
```

```

### 4. 主题集成 🎨

**自动适配**:
- 饼图：扇区颜色自动匹配主题

## 已知限制

### 当前阶段

1. **CSV 文件**:
   - 仅支持服务器本地文件（浏览器上传需前端开发）
   - 文件大小建议 < 1MB

2. **散点图**:
   - 暂不支持气泡图（变大小散点）
   - 颜色映射需手动指定系列

3. **导出功能**:
   - 仅 PNG 格式（SVG 需配置）
   - 无批量导出

## 经验总结

### 成功要素 ✅

1. **增量开发**: 先数据结构 → 解析器 → 前端 → 测试
2. **测试驱动**: 每个模块都有完整测试
3. **复用现有**: ECharts 内置功能满足大部分需求
4. **错误友好**: 清晰的错误提示和使用示例

### 技术挑战 🔧

1. **所有权问题**: ChartType 移动后借用
   - **解决**: 添加 Copy trait
2. **CSV 列访问**: 按名称还是索引？
   - **解决**: 两种方式都支持
3. **散点图数据格式**: points vs data
   - **解决**: 可选字段 + 验证逻辑
4. **图表渲染位置**: 初始版本在回合卡片外部
   - **解决**: querySelector 定位 Round 元素的 `.output-content` 区域

### 最佳实践 💡

1. **类型系统**: 充分利用 Rust 类型系统防止错误
2. **模块化**: 每个功能独立模块，易于测试和维护
3. **文档先行**: 实施计划文档帮助理清思路
4. **渐进式**: 先实现核心，再扩展功能
