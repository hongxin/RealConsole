# 可视化功能 Phase 3 深度分析与规划

> **制定时间**: 2025-01-22
> **基于版本**: v1.45.0 (Phase 2 完成)
> **目标**: 提升可用性、扩展能力、优化体验

## 执行摘要

Phase 2 已成功完成 4 种图表类型和 CSV 文件支持。Phase 3 应聚焦于**提升可用性**（浏览器文件上传）和**扩展分析能力**（更多图表类型），避免过度工程化。

**核心策略**: 优先解决用户痛点，快速迭代，保持精简

**P0 级痛点**（严重影响可用性）:
1. **CSV 文件仅支持服务器本地路径** - 用户无法直接上传数据
   - 影响：大幅降低 Web 终端的实用性
   - 用户反馈预期：⭐⭐⭐⭐⭐

**P1 级限制**（影响体验）:
2. **无数据预览** - 用户不知道 CSV 文件内容是否正确
   - 影响：错误图表需重新上传
   - 用户反馈预期：⭐⭐⭐⭐

3. **图表类型有限** - 某些分析场景无法满足
   - 影响：用户需要其他工具
   - 用户反馈预期：⭐⭐⭐

**P2 级限制**（高级需求）:
4. **导出格式单一** - 仅 PNG，无矢量图
   - 影响：打印质量差
   - 用户反馈预期：⭐⭐

5. **无数据导出** - 无法导出处理后的数据
   - 影响：需要手动复制数据
   - 用户反馈预期：⭐⭐

## Phase 3 需求分析

### 用户场景分析

#### 场景 1：数据分析师（核心用户）

**典型工作流**:
```
1. 有本地 CSV 文件（Excel 导出）
2. 想快速可视化分析
3. 需要调整参数（列选择、图表类型）
4. 导出图表用于报告
```

**当前痛点**:
- ❌ 无法直接上传文件（需 scp 到服务器）
- ❌ 不知道列名，需要先打开文件查看
- ✅ 图表类型基本够用
- ✅ PNG 导出可用

**优先需求**: 浏览器上传 > 数据预览 > 更多图表

#### 场景 2：开发者（日志分析）

**典型工作流**:
```
1. 有日志数据（CSV 或 JSON）
2. 想看趋势和异常点
3. 需要对比多个指标
4. 快速分享给团队
```

**当前痛点**:
- ❌ 服务器日志无法直接可视化（需手动下载）
- ✅ 折线图、柱状图够用
- ❌ 双 Y 轴缺失（CPU% vs 响应时间 ms）

**优先需求**: 浏览器上传 > 双 Y 轴 > 面积图

#### 场景 3：项目经理（进度报告）

**典型工作流**:
```
1. 有项目数据（Excel 表格）
2. 想生成图表用于汇报
3. 需要美观的图表
4. 导出到 PPT
```

**当前痛点**:
- ❌ 无法直接上传 Excel 数据
- ✅ 饼图、柱状图够用
- ❌ PNG 分辨率可能不够

**优先需求**: 浏览器上传 > SVG 导出 > 混合图表

## Phase 3 实施计划

### P0 阶段：可用性突破（v1.46.0）

**目标**: 解决最大痛点，大幅提升 Web 终端可用性

#### 功能 1：浏览器文件上传 🎯

**价值主张**: 用户可以直接从浏览器上传 CSV 文件，无需 SSH 访问服务器

**技术方案**:
1. **前端** (`src/web/frontend.rs`):
   - 添加文件上传 UI（拖拽 + 点击上传）
   - 读取文件内容（FileReader API）
   - 通过 WebSocket 发送文件数据

2. **后端** (`src/web/websocket.rs`):
   - 新增 `ClientMessage::UploadFile` 消息类型
   - 接收文件内容并暂存（内存或临时文件）
   - 返回文件 ID 供后续图表命令使用

3. **命令扩展**:
   ```bash
   # 原有方式（服务器文件）
   !chart csv /path/to/file.csv --type line ...

   # 新方式（已上传文件）
   !chart csv @uploaded_file_id --type line ...
   ```

**数据结构**:
```rust
// websocket.rs
#[derive(Deserialize)]
enum ClientMessage {
    Input { text: String },
    UploadFile { filename: String, content: String }, // CSV 内容
}

// 内存存储
struct UploadedFiles {
    files: HashMap<String, String>, // file_id -> content
}
```

**UI 设计**:
```
┌─────────────────────────────────────┐
│ 📁 Upload CSV File                  │
│ ┌─────────────────────────────────┐ │
│ │  Drag & Drop CSV file here      │ │
│ │  or click to browse             │ │
│ └─────────────────────────────────┘ │
│                                     │
│ Uploaded Files:                     │
│ • sales_data.csv (uploaded_001)     │
│ • metrics.csv (uploaded_002)        │
└─────────────────────────────────────┘
```

**开发估算**:
- 后端：2-3 小时
- 前端：3-4 小时
- 测试：1-2 小时
- **总计**: 6-9 小时

### P1 阶段：能力扩展（v1.47.0）

**目标**: 增加更多图表类型和数据处理能力

#### 功能 3：面积图（Area Chart）

**价值主张**: 适合展示累计趋势、堆叠数据

**技术方案**:
1. **后端** (`src/visualization/`):
   - `ChartType::Area` 枚举值
   - 解析器支持 `--stack` 参数（堆叠/非堆叠）

2. **前端**:
   - ECharts 配置：`type: 'line'` + `areaStyle: {}`

**命令示例**:
```bash
# 单系列面积图
!chart area --title "销售趋势" --x-axis "Q1,Q2,Q3,Q4" --series "销售额:100,120,140,160"

# 堆叠面积图
!chart area --stack --title "收入构成" --x-axis "Q1,Q2,Q3,Q4" --series "产品A:50,60,70,80" --series "产品B:50,60,70,80"
```

**开发估算**: 2-3 小时

#### 功能 4：双 Y 轴

**价值主张**: 对比不同量级的指标（如 CPU% vs 响应时间 ms）

**技术方案**:
1. **数据结构扩展**:
   ```rust
   pub struct Series {
       pub name: String,
       pub data: Vec<f64>,
       pub y_axis_index: Option<usize>, // 0 = 左轴, 1 = 右轴
   }
   ```

2. **命令语法**:
   ```bash
   !chart line --title "性能监控" \
     --x-axis "00:00,01:00,02:00" \
     --series "CPU%:45,52,48" \
     --series "响应时间(ms):120,230,180" --y-axis-index 1
   ```

**开发估算**: 4-5 小时

#### 功能 5：混合图表

**价值主张**: 在同一图表中混合折线图和柱状图

**技术方案**:
1. **命令语法**:
   ```bash
   !chart mixed --title "销售分析" \
     --x-axis "Q1,Q2,Q3,Q4" \
     --series "销售额:100,120,140,160" --type bar \
     --series "增长率:10,20,15,12" --type line
   ```

2. **前端**: 每个 series 可以指定独立的 type

**开发估算**: 5-6 小时

#### 功能 6：数据导出（CSV）

**价值主张**: 将图表数据导出为 CSV，方便进一步分析

**技术方案**:
1. **前端**: 添加"导出数据"按钮
2. **实现**: 将 chartData 转换为 CSV 格式，触发下载

**开发估算**: 2-3 小时

**P1 阶段总计**: 15-20 小时

## 技术架构设计

### 文件上传架构

```
┌─────────────┐         ┌──────────────┐         ┌─────────────┐
│  Browser    │         │  WebSocket   │         │  Memory     │
│  (FileAPI)  │────────>│  Handler     │────────>│  Storage    │
└─────────────┘         └──────────────┘         └─────────────┘
      │                        │                        │
      │ 1. Read file           │                        │
      │ 2. Send content        │                        │
      │                    3. Store with ID             │
      │                        │                        │
      │<───────────────────────┤                        │
      │    Return file_id      │                        │
      │                        │                        │
      │ 4. Chart command       │                        │
      │    @file_id           │                        │
      │───────────────────────>│                        │
      │                    5. Retrieve content          │
      │                        │<───────────────────────│
      │                    6. Parse & Render            │
      │<───────────────────────┤                        │
      │    Chart JSON          │                        │
```

### 数据流设计

```rust
// 1. 前端上传
ClientMessage::UploadFile {
    filename: "sales.csv",
    content: "月份,销售额\n1月,120\n2月,132"
}

// 2. 服务器存储
uploaded_files.insert("uploaded_001", csv_content);

// 3. 返回预览
ServerMessage::FileUploaded {
    file_id: "uploaded_001",
    preview: PreviewData {
        headers: vec!["月份", "销售额"],
        rows: vec![vec!["1月", "120"], vec!["2月", "132"]],
        total_rows: 2,
    }
}

// 4. 生成图表
!chart csv @uploaded_001 --type line --x-col "月份" --y-col "销售额"
```

### 内存管理

**策略**: LRU 缓存 + 大小限制
```rust
struct UploadedFiles {
    files: LruCache<String, String>, // 最多 10 个文件
    max_file_size: usize,             // 单文件 1MB
    total_size_limit: usize,          // 总计 5MB
}
```

**清理策略**:
- 会话结束自动清理
- 超过大小限制时清理最旧文件
- 文件 TTL：30 分钟

## 风险与挑战

### 技术风险

| 风险 | 影响 | 缓解措施 |
|------|------|---------|
| 大文件上传超时 | 中 | 限制文件大小 1MB，分块上传 |
| 内存占用过高 | 高 | LRU 缓存，总大小限制 5MB |
| WebSocket 传输失败 | 中 | 错误重试，友好提示 |
| CSV 解析错误 | 低 | 完善错误处理，显示行号 |

### 开发风险

| 风险 | 影响 | 缓解措施 |
|------|------|---------|
| 前端复杂度增加 | 中 | 分步实施，先 MVP 后优化 |
| 测试覆盖不足 | 高 | 每个功能需单元测试 + E2E |
| 文档滞后 | 中 | 同步更新用户指南 |

## 决策建议

### 立即开始 P0 阶段

**理由**:
1. 解决最大痛点（CSV 上传限制）
2. 用户价值最高（得分 8.0）
