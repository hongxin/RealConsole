# v1.51.0 会话历史加载 Bug 修复

**日期**: 2025-01-23
**Bug ID**: 会话刷新导致图表丢失和文本重复
**状态**: ✅ 已修复

## 🐛 问题描述

用户报告：当页面刷新后，历史会话出现以下问题：
1. **文本重复**: 显示 "✅ 图表已生成✅ 图表已生成"（重复两次）
2. **图表丢失**: 历史图表无法渲染或不显示

## 🔍 根本原因

### 架构分析

RealConsole 的会话持久化系统包含两个独立的历史记录：

1. **ConversationRound**: 对话回合历史
   - 存储字段: `id`, `user_input`, `ai_response`, `tools_used`, etc.
   - `ai_response` 包含清理后的文本（"✅ 图表已生成"）

2. **ChartHistoryEntry**: 图表历史
   - 存储字段: `id`, `timestamp`, `chart_data`, `round_id`, `command`, `title`
   - 包含完整的 ChartData 结构，关联到特定回合

### 问题根源

在 v1.51.0 初始实现中，`SerializableSession` **只包含** `rounds` 字段，**不包含** `chart_history` 字段：

```rust
// 旧版本 SerializableSession（有问题）
pub struct SerializableSession {
    pub id: String,
    pub name: String,
    pub created_at: DateTime<Utc>,
    pub updated_at: DateTime<Utc>,
    pub conversation_id: String,
    pub rounds: Vec<ConversationRound>,  // ✅ 包含
    // ❌ 缺少 chart_history
    pub metadata: Option<SessionMetadata>,
    pub version: String,
}
```

**导致的问题**：

1. 保存会话时，`chart_history` 不会被持久化到磁盘
2. 加载会话时，只恢复 `rounds`，不恢复 `chart_history`
3. 前端显示历史回合时：
   - 显示 `ai_response` 文本: "✅ 图表已生成"
   - 但**不发送 Chart 消息**，因为 `chart_history` 为空
   - 导致图表无法渲染
4. 可能的文本重复是因为前端某处重复处理了相同的 round 数据

## ✅ 解决方案

### 修改 1: SerializableSession 结构

```rust
// 新版本 SerializableSession（修复后）
pub struct SerializableSession {
    pub id: String,
    pub name: String,
    pub created_at: DateTime<Utc>,
    pub updated_at: DateTime<Utc>,
    pub conversation_id: String,
    pub rounds: Vec<ConversationRound>,

    /// 图表历史记录（v1.51.0 新增）
    #[serde(default, skip_serializing_if = "Vec::is_empty")]
    pub chart_history: Vec<ChartHistoryEntry>,  // ✅ 新增

    pub metadata: Option<SessionMetadata>,
    pub version: String,
}
```

**变更点**：
- 添加 `chart_history` 字段
- 使用 `#[serde(default)]` 确保向后兼容（旧会话文件没有此字段时默认为空数组）
- 使用 `skip_serializing_if = "Vec::is_empty"` 优化 JSON 大小

**文件**: `src/web/session_manager.rs:5, 34-36`

### 修改 2: Session::to_serializable()

```rust
pub async fn to_serializable(&self) -> SerializableSession {
    let rounds = self.get_rounds().await;
    let name = Self::generate_session_name(&rounds);
    let updated_at = rounds.last().map(|r| r.timestamp).unwrap_or(self.created_at);
    let metadata = Some(SessionMetadata::from_rounds(&rounds));

    // v1.51.0: 获取图表历史
    let chart_history = self.chart_history.read().await.clone();  // ✅ 新增

    SerializableSession {
        id: self.id.clone(),
        name,
        created_at: self.created_at,
        updated_at,
        conversation_id: self.conversation_id.clone(),
        rounds,
        chart_history,  // ✅ 包含图表历史
        metadata,
        version: env!("CARGO_PKG_VERSION").to_string(),
    }
}
```

**变更点**：
- 在序列化时获取并包含 `chart_history`
- 使用 `read().await.clone()` 安全地读取共享状态

**文件**: `src/web/session.rs:711-721`

### 修改 3: Session::from_serializable()

```rust
pub async fn from_serializable(
    serializable: SerializableSession,
    config: Config,
    registry: CommandRegistry,
) -> Self {
    let mut session = Self::new(config, registry).await;

    session.id = serializable.id;
    session.created_at = serializable.created_at;
    session.conversation_id = serializable.conversation_id;

    // 恢复回合历史
    {
        let mut rounds = session.rounds.write().await;
        *rounds = serializable.rounds;
    }

    // v1.51.0: 恢复图表历史（在独立作用域中，确保锁被释放）
    {
        let mut chart_history = session.chart_history.write().await;
        *chart_history = serializable.chart_history;  // ✅ 新增
    }

    session
}
```

**变更点**：
- 在反序列化时恢复 `chart_history`
- 使用独立作用域确保 RwLock 正确释放

**文件**: `src/web/session.rs:747-751`

### 修改 4: handle_load_session() - 发送 Chart 消息

```rust
match manager.load_session(session_id) {
    Ok(serializable) => {
        // 恢复会话数据到当前会话（恢复回合历史和图表历史）
        {
            let mut rounds = session.rounds.write().await;
            *rounds = serializable.rounds.clone();
        }

        // v1.51.0: 恢复图表历史
        {
            let mut chart_history = session.chart_history.write().await;
            *chart_history = serializable.chart_history.clone();  // ✅ 新增
        }

        // 发送 SessionLoaded 消息
        let response = ServerMessage::SessionLoaded {
            session: serializable.clone(),
        };
        sender
            .send(Message::Text(serde_json::to_string(&response)?))
            .await?;

        // v1.51.0: 为历史会话中的每个图表发送 Chart 消息
        // 这样前端在加载会话时就能正确渲染图表  // ✅ 新增
        for chart_entry in &serializable.chart_history {
            if let Some(ref round_id) = chart_entry.round_id {
                let chart_msg = ServerMessage::Chart {
                    round_id: round_id.clone(),
                    chart_data: chart_entry.chart_data.clone(),
                };
                sender
                    .send(Message::Text(serde_json::to_string(&chart_msg)?))
                    .await?;
            }
        }
    }
}
```

**变更点**：
- 恢复 `chart_history` 到当前会话
- 遍历所有历史图表，为每个图表发送 Chart 消息
- 前端收到 Chart 消息后会正确渲染图表

**文件**: `src/web/websocket.rs:2164-2190`

## 🎯 向后兼容性

### 兼容性保证

1. **旧会话文件**: 使用 `#[serde(default)]`，旧会话文件（没有 `chart_history` 字段）会自动初始化为空数组
2. **序列化优化**: 使用 `skip_serializing_if = "Vec::is_empty"`，没有图表的会话不会包含此字段，节省空间
3. **版本号**: SerializableSession 包含 `version` 字段，未来可用于更复杂的迁移逻辑

### 数据迁移

不需要手动迁移数据。旧会话文件会自动兼容，只是不包含图表历史（符合预期）。

## 📝 经验教训

### 设计教训

1. **状态分离的陷阱**: 将 `rounds` 和 `chart_history` 分开存储虽然符合关注点分离，但在持久化时需要**同时**保存两者
2. **完整性检查**: 序列化/反序列化时应该检查所有相关状态是否都被包含
3. **测试覆盖**: 需要测试完整的"保存-加载"周期，不只是新数据的生成

### 架构思考

这个 bug 暴露了当前架构的一个根本问题：**图表数据与回合数据的关联是隐式的**（通过 `round_id`），而不是显式的。

未来优化方向（参见 `architecture-evolution.md`）：
- **Phase 1**: 引入 `StructuredOutput` 枚举，统一所有结构化输出
- **Phase 2**: 将 chart 数据直接嵌入 ConversationRound，或使用统一的输出抽象
- **Phase 3**: 消除特殊标记 hack，使用类型安全的输出系统
