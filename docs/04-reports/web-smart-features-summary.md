## 三、意图理解方案设计

### 3.1 方案对比

**方案 A: Intent DSL 集成** ✅ 推荐

| 优势 | 数据 |
|------|------|
| 实现复杂度 | 低 (~100行) |
| 代码复用 | 100% |

| 场景覆盖 | 80% |
| 符合极简理念 | ✅ |

**方案 B: Task 系统集成** ⚠️ 暂不推荐

| 特性 | 数据 |
|------|------|
| 实现复杂度 | 高 (~500行) |
| 代码复用 | ~60% |
| 性能 | >2s |
| 场景覆盖 | 100% |
| 符合极简理念 | ❌ |

**结论**: 采用方案 A，保持极简

### 3.2 工作原理

**三层架构**：

```
Router 层 (天)
  ↓
Orchestrator 层 (人)
  ↓
Executor 层 (地)
```

**示例流程**：

```bash
# 输入
% 帮我查看最近的git提交并总结

# 处理流程
1. Router: 识别为自然语言
2. IntentMatcher: 匹配到 git_log_summary
3. TemplateEngine: 生成执行计划
   - 步骤1: 执行 git log -10 --oneline
   - 步骤2: LLM 总结
4. Workflow: 依次执行并返回结果
```

### 3.3 实现规划

**Phase 3: Task 集成** (按需)
